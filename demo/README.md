# Demos

Each demo is a folder here, run with `./platform demo <name>`. Each one runs a check from the take-home test the repo began as ("the brief"). It prints every command it runs, as `$ kubectl ...`, with its output indented below, explains what it's doing in `# ...` notes, and ends with a pass or a fail.

Every demo runs on a real environment: `./platform demo <name> [dev|staging|prod]`, prod (:8080) by default. At each step it prints a **▶ Check** box: which Grafana dashboard, Loki query or Argo CD page to open (as a link, with the environment already picked), and what you should see there.

| Demo | What happens | Time |
| --- | --- | --- |
| [`contract`](contract/run.sh) | the brief's contract table, checked live and read-only: `ready` healthy, `out/kubeconfig.yaml` works, the Deployments in dev, staging and prod, each endpoint on :8080, `/admin/*` refused (403), the Grafana login, Prometheus and Alertmanager, restart policies, the volumes that keep data | <1 min |
| [`release`](release/run.sh) | a new version of orders-gateway through `./pipeline`: CI, dev (syncs by itself), then staging and prod, each stopped at its Sync point: Git has the new version, Argo CD shows OutOfSync, the pods still run the old one. Then Sync, and the pods roll one at a time under load. Fails if fewer than 99.5% of requests meet the SLO. The version stays released; it prints the rollback. `release staging` stops after staging. `RELEASE_PAUSE` sets the hold at each Sync point (default 30 s) | ~10 min |
| [`alert`](alert/run.sh) | under load: the app's fault switched on in each pod from inside the cluster (`/admin/fault` is refused from outside), so 30% of requests fail; the availability fast-burn alert goes pending, then firing, reaches Alertmanager and the local receiver with its runbook link; the fault switched off (also if the demo is interrupted), and the alert resolves | ~15 min |
| [`chaos`](chaos/run.sh) | delete a pod, then drain a worker of the app's pods; the disruption budget lets only one go at a time; fails if fewer than 99.5% of requests meet the SLO. Staging or prod | ~3 min |
| [`gitops-revert`](gitops-revert/run.sh) | a bad config commit (30% of requests fail) to the environment's file, `apps/orders-gateway/cd/<env>.yaml`, on the in-cluster Git server; Argo CD syncs it (staging and prod at their Sync point), then `git revert` heals it. An interrupted run reverts it | ~5 min |
| [`platform-chaos`](platform-chaos/run.sh) | under load: deletes a Traefik pod, a CoreDNS pod, the Argo CD repo server and application controller, Prometheus and the Kyverno admission controller, one at a time; shows each come back and what the app needed from it; fails if fewer than 99.5% of requests meet the SLO | ~3 min |
| [`autoscale`](autoscale/run.sh) | k6 sends a fixed 20 requests/s (`AUTOSCALE_RATE`), mostly CPU-heavy `/work`; the HPA scales up (prod 3 → 6, staging 2 → 4), then back about 5 minutes after the load stops. Staging or prod | ~8 min |
| [`policy`](policy/run.sh) | Kyverno refuses an unsigned image and a `:latest` image in the environment's namespace, printing which policy refused each and why; a signed image is admitted (dry run). Nothing runs | <1 min |
| [`hello-world`](hello-world/) | a second app through the whole CI/CD, next to orders-gateway in dev, staging and prod: `./pipeline ci --version`, `cd` dev → staging → prod, a refused out-of-order promotion, a rollback, then a minute of traffic and its metrics and logs side by side in Grafana. It stays running to play with; `./platform demo hello-world clean` tears it down | ~7 min |

`./platform demo clean` tears `hello-world` down, and removes anything older versions of the demos left (a copy of prod in namespace `demo`, demo branches in the in-cluster Git server).

**How they run.** k6 sends traffic through Traefik to the environment the whole time. Each demo changes the environment only the way it says (killing pods, a node drain, the fault switch, a Git commit, a release) and ends by checking it is Synced, Healthy and serving again. `release` and `hello-world` run on the host, because they drive `./pipeline`; the others run in the toolbox and share [`lib.sh`](lib.sh): load and narration, the **▶ Check** boxes, and the in-cluster Git helpers.
